## Context

2026-10-08 分析基线：六项技能各 69 行，五份执行资源在各技能中自包含复制；当前离线结构校验及 19 项测试曾通过，未运行固定原生制品验收。下列是目标设计，不是完成报告。

已观察的问题：内层 cli.py 等待 600 秒后将超时转成退出 1 与 result=unknown，外层 command_gateway.py 等待 900 秒且只按退出码分类，导致 UNKNOWN 丢失；输出目录只有计划和回执也可能返回零退出；同步测试依赖兄弟插件目录。参见 proposal.md 与四份增量规范。

## Goals / Non-Goals

**Goals:** 一套公开共享契约支持单独安装和插件调用；原生命令与结果事实绑定固定制品；任务恢复不丢失未知语义；交付可保存重开并追踪修订。

**Non-Goals:** 不新增每个命令一项技能，不引入账号/付费机制，不宣称输入摘要是沙箱；不自动建立 Git/公开发行，不在本次实现所有原生功能、所有宿主或平台。

## Decisions

### 1. 技能保持六项，内容按职责分层

use 只编排，不维护第二套参数；CLI 维护单位（point）、跨页/屏幕坐标、页面索引差异、对象 ID、步骤引用和发现结果；document/layout/export 分别维护领域流程。每项按需携带 references/examples，跨技能只用名字和有效来源，不引用兄弟相对路径。skill-suite.json 是技能集合事实源。

保留运行资源自包含分发；开发维护采用一份明确的 canonical 资源及确定性复制/漂移校验，避免六份手工分叉。是否存在真实挂载路径应由宿主确定，/mnt/skills/user 只在真实挂载时有效；文档明确实际 SKILL_DIR 解析规则，并统一现有校验与工作区路径约定。比将所有技能改成薄包装更可靠，因为用户可独立安装单项。

### 2. 内部结构化结果与公开 stdout 分离

保留 cli.py 原生 argv 透传和原生 stdout/stderr 行为；增加供网关使用的独立机器结果通道（显式结果文件参数），不能将元数据混入 MCP stdio。启动器在该通道写版本化结果，包含 status、reason、exitCode、started、terminationVerified、可用日志引用和时间。网关优先读取完整结果；缺失、截断、未知 schema 或身份不一致时保守记录 UNKNOWN，不仅根据退出码推断原生状态。

直接 argv 入口不自动承诺任务网关的输入保全和完整回执能力。短任务默认等待保持兼容，并允许明确配置；长驻 MCP 跟随宿主连接/中断生命周期，不沿用短任务 600 秒限制。显式区分启动前失败和启动后不确定。组合测试使用受控 Python 子进程模拟挂起/退出，不需要真实原生安装。

### 3. 任务身份与恢复

新增回执 schemaVersion，并保留现有 status、stdout、stderr、automaticReplay=false、completeAcceptance=false 的兼容读取。新增 runId、start/finish 时间、runtimeIdentity、plan/catalog/input/resource 摘要、stepResults、checkpointRefs、termination 状态和 recoveryAction。计划保存摘要和日志引用；真实输出解析失败时保留原始日志。

目录查询与编辑是独立进程，但编辑步骤始终在一个原生会话运行。检查点只标记已写入且验证可重开的工程；支持的安全阶段可显式插入保存步骤，不能为了检查点改变原有命令含义。确认重开后的对象身份，不能直接把内存 ID 当作跨会话稳定标识。

未知结果以 runId 查询本地回执、相关进程及检查点，不能伪造服务端 operation/submitId 接口。既有状态不足、进程未停止或产物无法核对时仅给出只读诊断，绝不重跑整批。输入摘要属于检测机制；工作副本保护原件，不能保证回滚外部副作用。

### 4. 验收管线

任务契约明确期望工程、页数/尺寸/关键内容、导出格式、警告处理标准、修改范围与需要保留的原件。验收解析 fixed CLI 实际返回结构；未知版本返回兼容性缺口，禁止凭研究源码猜字段。

```mermaid
flowchart LR
  I[任务契约与输入] --> D[固定运行时与目录发现]
  D --> P[计划与身份落盘]
  P --> E[单会话执行]
  E --> B[预检及业务结果]
  B --> S[工程保存与新会话重开]
  S --> A[产物身份与逐页预览]
  A --> J[结构与视觉审阅]
  J --> R[范围内显式修订或交付]
  E --> U[UNKNOWN 核对]
  U --> C[验证检查点和剩余步骤]
```

产物清单包括 path、format、byteCount、sha256、来自哪个 run/工程和适用检查。页面预览绑定工程和页号；审阅记录 rubricVersion、reviewer/来源、page/item/story 定位、问题及结论。缺参考图用任务规范；不照搬 Dreamina 灯光/材质 rubric。PDF/X 内部检查与外部认证分开。

### 5. 测试和证据

分层：结构及引用 → 参数/拒绝边界 → 真子进程组合 → 离线场景 → 固定原生 → 插件宿主 → 创作审阅。前三层在独立源检出使用临时 fixture；原生首验在授权后使用隔离 runtime-home，绑定版本与二进制摘要。

源包负责原生和共享契约证据；插件负责宿主与任务编排证据。不能用 TRACE、模板字段或通过数量代替实际行为；未运行层保持 NOT_RUN。矩阵初期仅声明已实测的 Python/平台组合，其他组合保持待验收。

## Risks / Trade-offs

- [固定制品与研究源码不一致] → 先运行目录/字段契约探针，保留差异，不偷换运行时。
- [增加回执字段影响旧消费者] → versioned schema，保留旧读取并对缺字段拒绝自动恢复。
- [超时进程仍写入] → 核对终止和产物；未经证实的停止保持 UNKNOWN。
- [复杂排版判断无法完全自动化] → 结构检查与人工/自动视觉结论分开，绑定同一候选。
- [多份自包含脚本增加维护成本] → canonical 内容和确定性分发，运行时不依赖源码工作区。
- [原生或宿主授权尚未给出] → 可继续离线实现/测试，但相应验收任务保持开放。

## Migration Plan

先写能暴露组合超时与缺产物的红灯测试，再实现 EX/AV 最小行为，随后补 SK 和 QG。保留旧脚本入口、六个技能名及 command/params。旧回执不覆盖升级，读取不足时标记待核对。发布前同步插件候选并完成兼容验证；回退使用先前已验证包与锁，不改用户工程/旧回执。实现与验收完成后才将增量规范同步到 openspec/specs 并归档。
