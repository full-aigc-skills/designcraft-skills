# 多栏刊物


执行具体方法前读取 [Craft 场景命令与参数](references/craft-methods.md)，按其中的对象选择、会话、输入替换和结果检查执行。

## 任务起点

先读取素材，确认交付用途、目标尺寸或时长、修改范围与必要格式。能从任务和素材确定的细节直接采用合理默认值；只询问会改变结果的缺失条件。

需要可见编辑器时交给 **designcraft-editor** 技能。独立安装：`npx skills add full-aigc-skills/designcraft-skills --skill designcraft-editor`。当前新增技能为本地候选，发布前使用本地配套插件，不把此安装命令当作已发布证明。

## 执行步骤

1. 确认稿件全文、字体、页数和尺寸，已有工程先检查页面与样式，避免新建覆盖。
2. 创建三栏首框与空白续框，用实际返回ID分别设置栏数和栏距。
3. 显式选择正文故事的UTF-8字节范围，创建并应用正文段落样式。
4. 用 `text.thread` 把第二页接到第一页，正文只输入一次。
5. 保存重开后核对同一故事的全文、框链顺序、三栏设置与溢出，再导出PDF及IDML。

示例是两页三栏刊物；自动页码、图片环绕、脚注迁移不在当前已验证范围。真实稿件需要逐页视觉检查，不能仅凭文字未溢出交付。
## 工具落地

用 open_document/new_document 管理文档，inspect_document 与 get_story 核对内容；execute 执行命令，save_document 保存，render_page 逐页检查。

先读取实际工具 schema，再填写参数；对象或文档 ID 使用返回值。查询到的命令必须在当前后端可用。保存前选择新输出路径，保留输入。需要的算法、格式或命令不存在时说明缺口，不能用相近名称冒充。

## 结果检查

- 无断文、重文和不合理的空栏。
- 图片不会遮住文字，标题层级可辨。
- 导出文本可读，字体替换情况明确。

对照用户目标检查实际内容，而不只检查进程退出码。局部编辑查看局部细节，版式任务查看整页，时间媒体查看起止与关键段。异常结果先检查当前工程，避免重复执行不可逆操作。

## 交付

返回可编辑工程、实际派生文件和简短说明：做了哪些修改、哪些步骤因当前能力未执行、需要用户判断的内容。只列真实存在且已经检查的文件。若用户随后返工，读取本次源工程并局部修改，保留已接受的内容。
