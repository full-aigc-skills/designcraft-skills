# UNKNOWN 后的恢复

- **请求：** 多步排版执行期间超时，用户希望“再运行一次”。
- **前置：** 留存当前 runId、计划摘要、原生部分日志和工作副本路径。
- **动作：** 只读核对进程终止、已有工程、步骤身份和可重开状态；向用户报告已知步骤与未知步骤。若回执记录了已完成的 `file.saveAs`，在新会话用 `file.open`、`document.inspect` 核对同一文件及摘要，再运行 `commands.py recover <原回执> --checkpoint-receipt <重开回执>`。
- **安全下一步：** 只有输出 `RECOVERY_READY` 且明确列出 `remainingPlan` 时，人工审阅后才可作为新计划显式提交；已完成步骤及失败步骤都不会自动重放。跨会话 `step:N` 引用要求基于重开 inspection 手工重绑。没有可验证检查点或仍为 `UNKNOWN` 时保持只读，不恢复写入、不重建工程、不重放全批计划。
- **验收边界：** 即便项目可重开，仍须核对变更和导出；未知步骤只能在证据补齐后单独续做。
- **状态边界：** 只读恢复计划不等于业务验收；新计划仍须单独运行、保存重开、核对产物并逐页审阅。
